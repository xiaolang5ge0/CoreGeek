## 1. P0 必改（不改=翻车/丢分）

### 1.1 协议层 protocol.py

- [ ] 常量：`IMP = "imp"`；`ACTIONS += ("destroy", "catch")`；
  新中立类型 `CHALLENGER_VEHICLE/DEFENDER_VEHICLE`；可控机器人 ID 段 `30000/31000`。
- [ ] `Unit.load`：解析 `isDriving`（bool，默认 False）。
- [ ] `Turn.load`：
  - `zones` 值需保留矿的 `remain` → 新增 `mine_remain: dict[Pos, int]`；
  - 解析 `teamOur.summonRobotList` → `summon_robots: tuple[Robot, ...]`（结构同 robot.roles）。
- [ ] `Turn` 新查询：`imp()`、`vehicles()`、`my_vehicle()`、`enemy_imp_visible()`、
  `half_of(pos)`（左下-右上对角线分半区，供矿区归属判断）。
- [ ] 指令构造器：`destroy_command(pos)`、`catch_command(pos)`。
- [ ] `blocked()` 特例：敌方小车格不可驶入、**己方小车格可驶入（=上车）**、小车格不可建造。

### 1.2 守卫层 rules.py

- [ ] `IMP_ONLY = {"destroy"}`；`destroy` 校验：目标 8 邻域内且是矿（zones 为 MINE_TYPES）。
- [ ] `catch` 校验：目标 8 邻域内、目标位置有**可见敌方 imp**（teamEnemy.roles 中 roleType=imp；
  注意敌方 imp 仅 destroy 站桩期间全图可见，其余按视野——看不到就发不出有效 catch，不硬猜）。
- [ ] `_check_move`：`unit.is_driving` 时允许 `distance <= 2`（其余仍 ==1）。
- [ ] `_check_attack` 的 controller 校验暂保持 `(WORKER, PIONEER)`，
  imp 能否控炮列**待实战确认**（任务书 4.4 attack"可用角色：全部"，4.7.1"控制3个角色"）。
- [ ] **可控机器人指令**：`check()` 的 `turn.find(unit_id)` 找不到时，回查
  `turn.summon_robots`；机器人可 `move`（targetPos 邻接 1 格）与 `attack`
  （无 controllerId、需 targetPos；仅夜晚——待确认）。
- [ ] `_check_use`：召唤令四件套（*RobotSummonOrder）必须携带 targetPos；
  位置约束（地图内、非任一基地建造区、非 NPC 处、不与己方待生成召唤位重叠）
  由 `BuildableMap` 已知信息 + 己方 pending 召唤位校验。

### 1.3 捣乱鬼 FSM（新模块 fsm_imp.py）

- [ ] 白天：选**对方半区**价值最高矿（按 `vendor_prices×10次` 收益排序），
  移动→站桩 destroy（记录进度，中断则重新计数）；路径避开敌方角色密集区（imp 无攻击能力，被抓=死）。
- [ ] 防被抓：8 邻域出现敌方角色且非站桩必要 → 撤退一步再继续；血量 <40% 直接撤回己方半区。
- [ ] 夜间：imp 无攻击能力，躲己方防御圈内安全格待命（或确认可控炮后参与防空）。
- [ ] **反捣乱（全队）**：brain 每回合检测可见敌方 imp——若在我方半区矿旁站桩，
  调度最近的可控角色（优先工人，视野 4 内）`catch`（+20 金币并除掉威胁）；
  catch 占用当回合动作，需与采矿/建造权衡（ imp 破坏损失 > 1 回合采集时必抓）。

### 1.4 lastCmdResult 解析（planners/task.py）

- [ ] 新格式：`[exitCode:N]\n[durationMs:N]\n<输出>`；超时 `[TIMEOUT]`、异常 `[JUDGER_ERROR]`、
  超 64KB 尾部 `[TRUNCATED]`。
- [ ] 解析函数改为：按行剥离状态头与 durationMs，把 `<输出>` 喂给现有
  `_on_cmd_result`；`[TIMEOUT]`/`[JUDGER_ERROR]` 记入 session 错误（不重试同一条命令原样重发）。
- [ ] 兼容旧格式（首行直接是输出）——防御式解析，避免平台灰度期两种格式并存。

### 1.5 召唤令策略接线（最小可用）

- [ ] 消耗品购买清单中加入召唤令评估（15/20/70/120）。
- [ ] 首个用途（低成本高收益）：**夜间肉盾/补刀**——夜晚清场压力大时，
  在基地防御圈内侧召唤小型机器人吸引火力（BOSS 夜 D4+ 评估）；`use` 后通过
  `summonRobotList` 获得控制权，夜间下 `move` 顶到墙外挡路（无指令=原地待命，天亮自动清除）。
- [ ] 进阶用途（P1）：下半场集结机器人 `attack` 对方基地/英雄（敌夜不能分辨来源，
  风险=无）——**冠军差异项**，初版先打通指令链路。

### 1.6 模拟器与测试

- [ ] `tools/simulate.py`：角色 HP 500、加特林 25、电磁 20×级；zones 带 remain；
  支持 destroy/catch/move2/小车；敌方 imp 简单 AI（站桩破坏）。
- [ ] 新测试：`test_imp.py`（destroy 进度/中断/被抓）、`test_catch.py`、
  `test_summon.py`（召唤位非法退券/旁移）、`test_last_cmd_result.py`（新格式解析）、
  `test_vehicle.py`（move 2/上车/敌车阻挡）、`test_half_mine.py`（半区判定）。

## 2. P1 冠军增量（新机制收益最大化）

### 2.1 数值重估 → 火力配置

- 加特林 L3：25×3=75 伤/回合（群体，90°锥）；
  电磁 L3：60 能量穿透（对直线集群伤害期望 ≈ 60+）；
  火箭 L3：全图 20×3，3 回合冷却（DPS 20/回合）。
  → **武器组合建议**：3 火箭起手不变（夜 1-2 远程全图清小怪），
  D2+ 起把部分火箭**换成/升级为加特林+电磁混编**（25/60 伤对中大型性价比远超火箭 20），
  依据实战浪潮构成（小型多→加特林，大型/BOSS→电磁+火箭）动态定。
  落点：`planners/layout.py` 武器类型选择 + `fire.py` 火力轮转支持三种武器。

### 2.2 HP 500 / 复活提前 → 激进参数

- `_maybe_medicine` 阈值 120 → 300（按新 HP 比例）。
- 工人夜间采矿危险半径 `WORKER_DANGER_DIST` 可从 3 收紧为 2~3 之间实测调优；
  小怪 5 攻对 500 HP = 100 回合才死 → **夜采容忍度大增**，Night1-3 全力采矿不变，
  D4+ 夜采可更贴近走廊（多挖多赚）。
- 复活=次日白天第 1 回合 → 死亡代价≈半晚经济；开拓者做任务**不必再因怕死而提前撤离任务点**；
  `PIONEER_FLEE_DIST` 可维持 1（贴脸才走）。

### 2.3 小车利用

- 谁上车：**开拓者优先**（任务点 2 完成后车就在附近；赶路省 1 回合/2 格 →
  任务速度加分直接受益）；驾驶不影响车上做任务/交易。
- 长上下文宝藏：祭坛远时开车 2 格/回合移动，显著提高"当天赶到"成功率。
- 实现落点：`fsm_pioneer` 移动决策读 `isDriving`，`path.next_step` 支持 2 步跳；
  `brain` 检测 `challengerVehicle` 位置，顺路规划上车格。

### 2.4 半区经济战（imp 攻 + 我方采矿选点）

- 选矿：优先**我方半区**矿（对方 imp 够不着我方半区？——不，imp 可跨半区行动，
  但对方 imp 破坏主要在其出发半区更省时；实战确认）。
  `fsm_worker` 选矿评分加"半区安全权重"。
- imp 收益模型：破坏一个铜矿 = 对方少 10 采×8 金 + 半区 10 回合不补刷 ≈ 80 金+连锁经济损失，
  vs 我方 imp 路程成本 → **值得做**；优先破坏对方**石矿**（断墙=断防）或当前高价矿。

### 2.5 任务速度分（score_1 = 奖励 + 5×标准/实际）

- `TaskPlanner` 预算从"稳"改"快"：`max_loops/max_cmds` 预算可适度放宽下限、
  收敛即锁定（已有 SOP），**部分完成也给通过率分** → 若临近超时且答案不完整，
  也要把已收割字段先提交（`score = 奖励×通过率`），**绝不空手到超时**。
- 每任务点任务总数有上限 + 30 回合刷新 → 两任务点轮转接取，开拓者路线
  CP↔TP1↔TP2 优化（小车加成后更划算）。

### 2.6 LLM 额度策略

- 每日 3 次上限不变（brain 已遵守）；errorCode=5 收到即**当日封禁非任务 LLM**
  （新兜底，防连续超限产生多余 errors）。
- 自进化任务期内不限次 → task 阶段 prompt/execute 循环不受 `_llm_budget_ok` 约束（现状 ✓）。

## 3. P2 风险与待实战确认

| # | 事项 | 现有假设 | 验证方式 |
|---|------|---------|---------|
| 1 | imp 能否操控武器(attack) | 假设不能，暂不给 imp 控炮 | 首战让 imp 夜间发一条 attack 观察合法性 |
| 2 | 可控机器人 attack 是否限夜晚 | 假设限夜晚（同角色） | 同上，白天发一条试探 |
| 3 | 半区归属判定（对角线哪侧归 challenger） | 按几何对角线 + 实测校准 | 首夜记录对方 imp 出现区域 |
| 4 | 我方小车格驶入即驾驶？移动 1 格下车规则 | 按任务书 4.6.4 实现 | 仿真验证 |
| 5 | catch 目标是否要求可见 | 要求可见才发（防指令错误=异常+1） | 代码保守处理 |
| 6 | destroy 期间 imp 被打断的判定时序 | 按"任一回合未执行即清零"实现 | 实战日志 |
| 7 | 召唤令每日 10 张上限的计数口径 | 按"每天 use 成功数"本地计数保守限 8 | 实战确认 |
| 8 | errorCode=5 是否计入异常 5 次 | 按会计入处理（严格限额） | 观察平台判罚 |

**异常红线（v2.0 强调）**：指令字段缺失/动作码非法 = 异常+1（5 次判负）；
执行失败（碰撞/无目标）≠ 异常。→ LegalityGuard 必须先于发送拦截一切"缺 targetPos"
的 destroy/catch/use 召唤令，宁可不发不发错。
