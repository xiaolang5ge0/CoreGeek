## 一.5 角色固化（用户指定）

| 角色 | 绑定 | 职责 | 优先级 |
|---|---|---|---|
| **炮手** | pioneer | 白天任务/买武器券/升级武器（**任务间隙插空升级**：任务途中/间隙也升级）；入夜前归位炮台操控位 | 1吃药 > 2买武器券 > 3升级武器 > 4入夜前归位 > 5任务流程 > 6接任务 > 7寻宝 |
| **修理工** | worker[0]（ID 最小） | **D1** 全力石料+建墙（一次采 12-14 再连续建）；**D2-D3** 建墙优先（检索缺口）→采铜/铁卖钱买券（**常备 5 石头**修墙）；**D3+** 白天预留回合回墙内（**回防粘性**：跨昼夜持续到进墙）；夜间升级/修复 | 1吃药 |
| **挖矿工** | worker[1] | 全天 采矿→卖钱→返回 循环；**返程 deadline**（白天70/夜间130，BFS/A\* 路径+6） | 1吃药 > 2(D1 石头>20 且墙<14)紧急建墙 > 3持续外出采矿（躲避机器人/判路径） |

**修理工夜间**：D3+ 夜**就位 repair_post**（内圈邻墙格，非只回家）并守内圈，**机器人清空前不外出采矿**；升级（用白天采购的券）→ 抢修受损<50%墙 → 无事守 repair_post。
**修理工抢修口径（用户补充 2026-09-22）**：修复阈值 = 墙血 <50%；正面墙优先；L1/L2 优先用升级券（升级=回满血+提上限），L3 升级券失效 → 只能用 WallFixer；无达标需求/无券 → 落回采矿。
**挖矿工售卖**：背包满 / 路过 vendor / 需要凑武器升级费 → 走向 vendor 卖出。

## 一.6 新闻经济（官方消息）

| 层级 | 做法 |
|---|---|
| 第一层（正则） | 解析官方消息的 **矿种（铜/铁/石）+ 停工/塌方/检修/故障/瘫痪/中断/塌陷… + 时间词（今天/明天/后天→起始偏移）+ 天数** → 维护 (事件, 起始日, 天数, 资源) 映射；**注意"复工/复产"会误匹配"修复工程"→ 用更长词组** |
| 第二层（LLM） | **确定性解析失败时**（未识别矿种/事件）→ 当日 LLM 兜底解析 `{ore,action,start_day,days}`；预测写入 `trace["news_pred"]` 便于调试 |
| 停工前 | 继续采该矿种**囤货**（选矿加权） |
| 停工期 | **优先卖**该矿种（高价，售卖加权 +50） |
| 恢复后 | 官方说"恢复" → **清空预测**，恢复默认 |

## 一.7 每日 LLM 上限

| 参数 | 值 | 说明 |
|---|---|---|
| LLM_DAILY_LIMIT | **3** | 每游戏日 LLM 上限（跨天重置）；**仅约束非任务期 LLM**。自进化任务执行期间（接取→结束）LLM **不限次且不计数**（接口文档 errorCode=5）——此前误将任务求解也套日限额，导致任务1用光额度后任务2 prompt 被丢弃（issue#23/#24 根因） |

## 三、术语定义（防歧义）

| 术语 | 定义 |
|---|---|
| **安全矿（B 方案）** | **以"机器人行军走廊"判定**：走廊 = 出生点质心 → 我方基地 的连线（半宽 CORRIDOR_WIDTH=5），但**只算距我方基地 > CORRIDOR_BASE_MARGIN=8 的部分**（近基地处有墙/炮塔保护）。矿落在走廊内 → 危险（夜间/临近入夜不采）。辅以 MAX_MINE_DIST=16（优先近矿）与"绝不深入敌方侧" |

| **围墙状态表（WallRegistry）** | 跨回合 Dict：Pos → {exists, level, health, is_front, breached_round, rebuilt_round}；只记事实，供修复/升级决策 |

### 17.4 P0-2 方案讨论（2026-10-09）——用户已选乙（结构校验）

背景：`_answer_suspect` 用子串嗅探"答案是不是报错文本"，与日志分析类任务**天然冲突**——这类任务的答案就是错误统计，"error/401/403" 恰恰是数据本身。

| 方案 | 内容 | 对"答案真是报错"的拦截力 | 评估 |
|---|---|---|---|
| 甲·最小改 | "error" 移出黑名单 + key "errors" 白名单 | 弱：真报错体也常用 `{"errors":[...]}` 格式，白名单挡不住；"401" 作统计键仍会误杀 | 修好 l1/l2，但同类误杀以后还会冒出来 |
| 乙·结构校验（推荐） | 答案能 parse 成 JSON、非空、无占位符 → 提交；任务文本/errorCode=2 反馈里能提取到必填字段时校验 key 存在（提取不到就跳过这层）；401/403/traceback 等**从否决项降为参考项**；真提交错靠 errorCode=2 重答兜底（IKK7ED l3 已实战验证该链路好使） | 强：报错文本（HTML 错误页 / `{"message":"Internal Server Error"}`）通常不是任务期望的 JSON 结构或缺必填字段，结构校验直接拦下 | 根治；代价不对称支持放宽：**误拦 = 丢整个任务+占点一整天，提交错 = 1 次重试** |
| 丙·删预检 | 完全删掉，只靠 errorCode=2 | 无预检 | 最简单；但回到"提交报错文本"的历史老坑（issue#16 时代真实发生过） |

> 注：此预检只影响"LLM 组答案"路径；脚本类 TOKEN 自动提交路径不受影响（本就有真实 TOKEN 锚定）。

### 17.5 P0-3 实施方案（2026-10-09，用户已采纳并实施）
